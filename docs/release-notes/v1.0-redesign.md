## What's in this release

The 15 commits between `52f98a65` (the redesign launch-pad on `main`) and the redesign tip add the **ecosystem model** (ADR-0010) and the **client-side Pattern Engine** (ADR-0011), replacing the wilting-plants + rain-cloud visual taxonomy and the Cloud-Function-driven 2-rule trigger.

### New features

1. **Mood Score `S_t = v × i/5`** — pure-Dart per-entry scalar in `[-1, +1]`. Sign mapping: Joy/Calm/**Okay** = +1; Sadness/Anger/Anxiety = -1. The Okay sign flip is documented and accepted as a retroactive change (ADR-0010 §2 trade-off).
2. **5 plant tiers, all visibly alive** — Flourishing / Thriving / Resting / Weathering / Storm Season. Driven by EWMA Garden Health `H_t = 0.15·S_day + 0.85·H_{t-1}`, weekly `H_0 = 0`. Bounded daily delta `≤ 0.15` ensures one bad day cannot crash the canvas. Storm Season specifically renders rain falling AROUND a sheltered garden — plants intact, lanterns brighter; never wilting.
3. **4 daily atmosphere states** — calmSunny / brightSunny / lightRain / storm. Driven by `avg_S_today`. Resets at local midnight. Decoupled from plant tier in code (separate pure-Dart services) and z-order (plants are not children of the storm overlay).
4. **5-algorithm Pattern Engine** running entirely client-side as pure-Dart functions:
   - **Mann-Kendall trend test** (14-day window) — `Z_trend < -1.96` → Tier 1.
   - **Sliding 5-of-7** — 5+ negative days in last 7 → Tier 2.
   - **3-consecutive S ≤ -0.6** → Tier 3.
   - **Z-score** (today vs 30-day baseline) — `z_day < -2.5` → Tier 3.
   - **CUSUM** change-point — sustained drops → Tier 3.
   Result documents at `users/{uid}/patterns/{date}` carry only numeric outputs + the resolved tier (no mood text — PII guard).
5. **Engine on, dispatcher off.** The engine writes `patterns/{date}` on every mood log. The legacy cheer-up dispatcher path is gated behind a new Remote Config flag `interventionDispatchEnabled` (default `false` in v1.0). Sprint 5 re-points the dispatcher at `patterns/{date}.triggeredTier` and flips the flag.
6. **Weekly Harvest cycle** — at the close of every 7-day window, the user's garden is archived (write-once) to `users/{uid}/weeklyGardens/{weekId}` and a fresh garden begins with `H_0 = 0`. Past weeks are browsable via a new History tab. The Pattern Engine's sliding windows do NOT reset on harvest (they read from the flat `users/{uid}/moods/` collection).
7. **Token economy** — first log of a calendar day = 5 tokens; each additional log adds 1 up to 10/day. Mood-agnostic by construction (`award_daily_tokens.dart` reads no `MoodType` / `MoodEntry` / `MoodScore`; enforced by file-level grep test). Missed days lose nothing. Visibility toggle in Settings; tokens still accumulate when the chip is hidden.
8. **Day/Night theme** — new fourth `ThemeModePreference.followDeviceTime` value flips between light/dark on local-clock cutoffs (07:00 / 19:00) without geolocation. Backward-compatible storage migration; existing users on `system` / `light` / `dark` decode correctly.

### Behind the scenes

- **Legacy `pattern_detector.dart`** moved from `features/garden/domain/` to `features/pattern_engine/domain/legacy_pattern_detector.dart` and marked `@Deprecated`. Retained as a regression baseline; CI keeps the legacy test file under `@Tags(['legacy'])`.
- **`functions/src/analyzePatterns.ts`** narrowed to insights-only role. `NEGATIVE_MOOD_CODES` no longer includes `'okay'` (mirrors the client-side flip). `interventionDispatchEnabled = false` means it does not feed the dispatcher.
- **`firebase/firestore.rules`** extended with `users/{uid}/patterns/{dateId}` (8-key allowlist, doc-id regex, write-once-per-day with same-day re-evaluation overwrite, no PII fields), and S5 stub denials for `users/{uid}/interventions/{id}` and `users/{uid}/cooldowns/{type}` (read allowed for owner, write denied in v1.0).
- **`firebase/test/firestore_rules.test.ts`** extended with 16 new emulator tests covering the new collections + denial cases.

## Known deviations from spec

**TC-27 (Mann-Kendall worked example).** Spec §7.27 prescribes `Z = -2.21 ± 0.005` on a steadily-declining 14-day window. Mann-Kendall's `S` statistic is integer-valued, so `Z` is quantized; the closest reachable values to -2.21 with `n=14` are -2.190 (S=-41) and -2.2445 (S=-42), neither inside the spec's stated tolerance. The TC-27 unit test pins both the user-facing tier-trigger condition (Z < -1.96) on a clearly-declining series AND the closest-achievable Z = -2.190. Tolerance softened to ±0.05 by architect amendment in ADR-0011 Consequences section. Algorithm tier-trigger semantics are unchanged. Spec §2.4 + §7.27 will be amended in the next spec revision.

## Migration notes for users on the existing v1.0

The redesign is read-side-compatible with existing user data:
- `MoodEntry` schema is unchanged — no migration needed.
- Past entries logged with `mood: 'okay'` will be re-scored as `+1` (positive) on read, instead of `-1`. This shifts the Garden Health and Atmosphere render for past data; the new Pattern Engine evaluates current windows only and does not retroactively trigger a tier.
- `users/{uid}/insights/`, `users/{uid}/cheerUpEvents/`, `users/{uid}/interventionState/`, `users/{uid}/settings/notifications/` are unchanged.
- New `users/{uid}/weeklyGardens/{weekId}` and `users/{uid}/patterns/{dateId}` collections start empty for existing users; the engine populates `patterns/` on the next mood log.
- New top-level user-doc fields (`tokenBalance`, `tokensEarnedToday`, `lastTokenEarnedDate`, `gardenSettings.dayNightMode`, `insightsDisclaimerAcked`) default to safe values when missing — no backfill needed.

## Demo script

End-to-end smoke (run on Android emulator + Web):

1. Sign in → onboarding → garden screen renders with `H_0 = 0`, Resting tier, calm-sunny atmosphere, empty 7-day strip.
2. Log a mood: Sad, intensity 4 → `S_t = -0.8`. Atmosphere recomputes (storm — `|avg_S| ≥ 0.3`); plants stay sheltered; day-1 strip cell shows negative score; `H_1 = 0.15 × -0.8 + 0.85 × 0 = -0.12` (Weathering tier).
3. Log again same day: Joy, intensity 4 → `S_t = +0.8`. Today's avg = 0 (calmSunny); plant tier updates per the EWMA fold.
4. Open `users/{uid}/patterns/{2026-05-12}` in Firestore console → doc present with all 5 algorithm outputs and `triggeredTier: null`.
5. Open `users/{uid}` → `tokenBalance` is +6 (5 from the first log of the day + 1 from the second).
6. Settings → toggle Day/Night to "Follow device time" → at 14:00 local theme is light; at 20:00 local theme is dark.
7. Force-advance to week boundary (test hook) → Weekly Summary screen appears with banner copy verbatim:

   > "Your garden this week has been harvested and saved to your history. A new week begins — a fresh canvas for your story."

   Tap "Continue to new week" → new garden with `H_0 = 0`. History tab shows the just-archived week with all entries browsable.
8. Verify NO cheer-up banner fires even when the engine writes a triggered tier (gate is off in v1.0).
