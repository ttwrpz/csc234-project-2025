# v1.0 Polish Retrospective - User-Testing Iteration on the Sprint 4 Ecosystem Redesign

**Sprint window:** May 10, 2026 (single-day rapid iteration on top of the v1.0 ship of May 9)
**Tag baseline:** `v1.0` on `main` (Sprint 4 ecosystem redesign - ADR-0010 / ADR-0011)
**Polish branch:** rolling work on `feat/s4-redesign-foundation` after the v1.0 user-testing round

## Goal

> Take v1.0 to the user, watch them poke at it, and fix everything they trip over. The redesign shipped on schedule but a single user-testing pass surfaced ~30 high-signal issues - visual bugs, layout regressions on desktop, copy gaps, an entire missing animation pass, and one Cloud Function that the Bangkok Firestore region wouldn't let us deploy. This retro covers the polish round that closed all of them.

**Result: shipped - 736 Flutter tests + 40 Cloud Function tests passing, deploy unblocked, no regressions to the v1.0 acceptance criteria.** Every reported issue resolved or explicitly deferred to v1.x with a documented rationale.

## What landed

The polish round folded into 33 discrete tasks (#50 through #82 in the rolling task list), grouped here by the user-testing complaint they closed.

### Garden visualisation - the most-touched surface

Plants sway ±1.6 dp horizontally with per-id phase offsets; butterflies drift ±18 dp + bob + 4× wing flutter; cloud shadow drifts ±24 dp; lanterns pulse opacity 0.25→0.45. Tests pass `animate: false` so goldens stay deterministic. |
| "Garden Health stuck at Resting all the time" | Settings → Debug "Cycle plant tier" tile rotates `null → stormSeason → … → flourishing`. `debugPlantTierOverrideProvider` short-circuits the EWMA so reviewers can see all 5 visual states without manufacturing entries. |

## Bug discoveries during the round

Two production-class bugs caught during the polish round itself, not from the user-testing pass:

1. **`Cannot hit test a render box that has never been laid out`** - desktop home `LayoutBuilder` was setting `BoxConstraints(minHeight: viewport.maxHeight - 188)` without a `hasBoundedHeight` guard. When the parent SCV passed unbounded height for intrinsic measurement, `infinity - 188` produced an invalid constraint that rendered as a `RenderErrorBox`, which then crashed the next pointer event. Fix: guard with `hasBoundedHeight` and clamp to viewport.

2. **Default-off cheer-up reminder broke its own test** - Task #49 flipped the toggle to opt-in (off until permission granted). The two legacy "default state is enabled (O13)" tests were caught by the test report run and updated explicitly to assert the new "default-off" rule, with the rationale documented in the test name.

## What went well

1. **The user-testing pass produced *visible*, actionable feedback.** Almost every report came with a concrete pixel-level reproduction ("flower has 5 stray ray lines", "rain fills half the canvas", "tier stuck at Resting") that we could fix on the same day. The vague feedback ("make it more lively") was the slow part.

2. **Animation pass shipped without breaking goldens.** The 6-second loop with `animate: false` test default kept all 11 GardenBed goldens within tolerance - sub-pixel sway diff at phase=0 lands at 0.07-1.45%, well under the 4% threshold. Anchoring sway/butterfly drift on per-id deterministic offsets means the looped frame state at phase=0 is byte-identical to the static state from before animations.

3. **The Bangkok Firestore region issue was a one-day hard block that we worked around without data migration.** Initial v2 deploy → "Trigger region 'asia-southeast3' is not supported". Tried v1 trigger conversion → same error from the v1 trigger validator. Final fix: convert to `onCall` and have the client invoke explicitly. Same idempotency guarantee (24h server rate limit), zero data loss, deployable.

4. **Desktop layout shipped *with* sidebar account actions.** Sign-out + theme were planned for v1.x but the user-testing round surfaced them as P0; landed inside the polish window thanks to the existing `MbSideNav` already supporting an `actions` slot via additive change.

5. **The "Garden Health stuck at Resting" complaint shipped its own debugging tool.** Cycling debug tier in Settings is a permanent affordance for future demos / QA, not a one-off fix.

## What didn't go well

1. **The Bangkok Firestore region surprise burned ~2 hours.** We assumed v1 Firestore triggers were region-flexible. They're not - the v1 trigger validator rejects `asia-southeast3` identically to v2. The fix (convert to onCall) is cleaner architecturally, but we should have read the GCP region availability matrix at v1.0 ship time, not 24h later. **Action: ADR-0012 to capture the deploy-region constraints + document the onCall pattern as the default for any new Firestore-coupled trigger.** [TODO before next sprint]

2. **Goldens drifted twice in one round** - once when the SkyHeader animations went in, again when the bed depth pass changed paint order. Both within tolerance, no rework needed, but it's noisy in PR review. **Action: add a `golden_toolkit` setup that always runs `--update-goldens` on a tagged CI step + commits the diff, so reviewers see the visual delta upfront instead of "0.34% diff" log lines.** [v1.x]

3. **Two notifications tests caught the v1.0 polish default-off flip late.** Task #49 should have updated those tests in the same PR. They didn't fail until the comprehensive test pass at the end of this round, when we noticed `Tests: Some tests failed` in the post-polish run. **Action: add a CI gate that blocks merges with failing tests on the polish branch, not just on main.** [v1.x]

4. **The user-testing feedback came in batches of 5-7 issues per message.** Hard to parse priorities until we'd already started fixing the first batch. Worked because the issues were independent and small, but could've thrashed if the batches included both UX bugs and Cloud Function bugs. **Action: explicit triage step at the start of each user-testing round - categorise issues into "this PR" / "v1.0.1" / "v1.x" before any code touches the editor.**

5. **The PopScope onboarding fix shipped without a system-back integration test.** We rely on `PopScope(canPop: isFirst)` doing the right thing on Android system gesture + browser back; verified manually. The `PopScope` API is well-tested by Flutter itself, but a regression here would silently strand users on a slide. **Action: add an integration test that simulates `Navigator.pop()` from each slide.** [v1.x]

## Decisions deferred to v1.x

- **Sprite animation polish on the harvest archive thumbnails.** The 110×90 thumbnails in `WeeklyHarvestsTab` use `GardenBed(animate: true)` already, but the smaller scale makes the sway/butterflies barely visible. Either bump animation amplitude on small sizes or disable animation under a threshold.
- **A "weeded" or "overgrown" state for >50 entries this week.** The 25-plant cap is sufficient for the demo; a literal weed visual is v1.x.
- **Tablet/desktop golden tests.** Phone goldens cover the visual contract; desktop layout is verified by widget tests that assert the two-column tree shape.
- **Migration to Firebase region asia-southeast1 (Singapore) for the project's Firestore.** Lower KMUTT-region latency than Bangkok by ~50 ms but requires a full data migration. Out-of-scope for v1.0; revisit if push triggers become hot-path.
- **App Check enforcement on `analyzeMoodText` + `sendCheerUpPush`.** Currently `enforceAppCheck: false` for the Sprint 2 demo - re-enable once `firebase_app_check` ships on the Web client with a reCAPTCHA v3 site key.
