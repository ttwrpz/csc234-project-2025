\section*{Executive Summary}

\paragraph{What we built.} MoodBloom is a cross-platform Flutter mood-tracker
for Android and Web. The user logs a mood + 1--5 intensity + optional text;
a client-side Pattern Engine runs five statistical algorithms (Mann-Kendall
trend \cite{mann1945trend,kendall1975rank}, sliding 5-of-7 negatives,
3-consecutive intensity, Z-score, CUSUM change-point \cite{page1954cusum})
and dispatches a tiered intervention (gentle breathing $\to$ journaling
$\to$ curated crisis resources) when warranted. Plants in the garden are
never destroyed; every mood is rendered as weather.

\paragraph{How we built it.} Five sprints (S1 planning, S2 walking
skeleton, S3 AI foundation, S4 ecosystem redesign, S5 safety surface),
orchestrated through Claude Code with \textbf{four named subagents} that
enforce role separation (\texttt{architect}, \texttt{flutter-engineer},
\texttt{qa-engineer}, \texttt{security-reviewer} at
\texttt{.claude/agents/}). Every sprint started in Plan Mode with explicit
``do not start implementation until I approve the plan'' gates
(\texttt{.claude/prompts/sprint-\{2,3,4,5\}-kickoff.md}). Six write-time
hooks (\texttt{.claude/hooks/settings.json}) enforce format, analyze,
secret-scan, no-\texttt{print}, layer-purity, and post-commit
domain-test invariants.

\paragraph{Outcomes.} At \texttt{v1.5}: $\sim$1{,}236 Flutter test cases
across 156 files, 78 Cloud Function jest tests, 15 Firestore rules
emulator tests in CI (\texttt{.github/workflows/ci.yml}). 14 ADRs
accepted (\texttt{docs/adr/0001}--\texttt{0014}) and 9 handoff briefs
(\texttt{docs/handoffs/HB-001}--\texttt{HB-009}). The bipolar/medical
disclaimer is enforced at four locked surfaces; Tier 3 interventions
are guarded by a \textbf{type-level fence} so Gemini cannot be called
even if a future refactor tried (proved at
\texttt{tiered\_intervention\_dispatcher\_test.dart} TC-40).

\paragraph{Honest learnings.} Multi-agent dispatch had real friction ---
most of it documented in \texttt{docs/retros/sprint-\{2,3,4,5\}-retro.md}
and detailed in \S\,\ref{sec:drift} below. Two artifacts the rubric asks
about (\texttt{docs/qa/perf-profile.md},
\texttt{docs/qa/a11y-sweep.md}) were not produced before the report date
and are flagged in \S\,\ref{sec:perf-a11y} and Appendix~A as outstanding.
We did \emph{not} run \texttt{flutter test --coverage} to derive a
percentage for this report; ``coverage not yet committed'' is honest
where the alternative would be fabrication.

\paragraph{Note on prompt template fidelity.} The D2 prompt contained
sample code (Firestore rules, regex-based PII stripping, a hypothetical
EWMA $\alpha$=0.10$\to$0.15 rework) that does not match the shipped
codebase. This report quotes the actual rules, documents the actual
PII discipline (length-only logging + a canary test), and cites a real
S4 architectural tension ($\alpha$=0.20-vs-0.15) from the retro. Where
the template implied artifacts that don't exist
(\texttt{docs/security/} directory, snake\_case feature-flag names, the
logger routing to Crashlytics), the report says so.

\subsection{Agent context drift --- challenges encountered}\label{sec:drift}

This section is honest. The retros documented four real friction
patterns, each with a mitigation actually adopted in the next sprint.

\paragraph{Drift 1: Parallel-agent working-tree collision (S2 Day 5).}
Two background agents (\texttt{qa-engineer} on
\texttt{feat/qa-widget-tests} and the orchestrator preparing
\texttt{feat/5.1-history-scaffold}) shared the same checkout. The second
agent's \texttt{git checkout -b} silently flipped the first agent's
branch context mid-dispatch.

\begin{quote}\itshape
``Parallel agents share the same working tree. When \texttt{qa-engineer}
ran \texttt{git checkout -b feat/qa-widget-tests} while
\texttt{feat/5.1-history-scaffold} was still being prepared by the
orchestrator, the orchestrator's WT silently flipped branches.
Detected and untangled, but it was a 5-minute scare.''
(\texttt{docs/retros/sprint-2-retro.md:95})
\end{quote}

\textit{Mitigation (adopted S3):} route one of any parallel pair through
\texttt{git worktree add ../<task-name> <branch>}.

\paragraph{Drift 2: File smearing across parallel branches (S3 Day 2).}
Two \texttt{flutter-engineer} agents working on the image picker (D2.3)
and the garden canvas (D2.4) hit the same WT, both wrote files, neither
committed before time-out, and the second agent's branch ended up
holding a smeared mix from both tasks.

\begin{quote}\itshape
``Two background agents (D2.3 image picker + D2.4 garden canvas) hit
the same checkout. Each created its branch but neither committed before
timing out, leaving a smeared mix of files on the second agent's branch.
Recovery: snapshot the working tree, partition by inspection, restore
each file set onto its correct branch.''
(\texttt{docs/retros/sprint-3-retro.md:98})
\end{quote}

\textit{Mitigation (rest of S3, mandatory by S5):} serial dispatch on
file-mutating tasks OR \texttt{isolation:"worktree"} on every dispatch.

\paragraph{Drift 3: Spec-vs-implementation tension on the EWMA $\alpha$
(S4).} The spec (\S 2.2) fixes Garden Health EWMA at $\alpha=0.15$. During
implementation, the sprint floated $\alpha=0.20$ for a more responsive
canvas. The \texttt{architect} ruled in favour of the spec value, citing
the autocorrelation derivation at lag-1 typical of daily mood time-series
\cite{smit2022ewma}, because the bounded daily delta
$|\Delta H| \le 0.15$ is what guarantees one bad day cannot crash the
canvas.

\begin{quote}\itshape
``EWMA $\alpha$ choice was contested. Spec \S 2.2 fixes $\alpha=0.15$.
The sprint floated $\alpha=0.20$ for a more responsive canvas; the
architect ruled in favour of the spec's $\alpha=0.15$ [\ldots] The
bounded daily delta $|\Delta H| \le 0.15$ is what guarantees one bad
day cannot crash the canvas.''
(\texttt{docs/retros/sprint-4-retro.md:36})
\end{quote}

\textit{Mitigation (S4 onward):} spec-citation in handoff briefs;
architect-only sign-off on any deviation from
\texttt{.claude/specs/sprint-4-5-spec.md} constants.

\paragraph{Drift 4 --- Six recurring dispatch failure modes (S5).} S5
catalogued six concrete patterns: agent worked in orchestrator cwd;
agent reported ``done'' with uncommitted changes; agent branched off
\texttt{main} instead of the integration branch; rate-limit mid-task;
socket error mid-task; work-in-worktree-but-uncommitted. First salvage
cost $\sim$30 minutes; the sixth cost five.

\begin{quote}\itshape
``Six dispatch salvages. Sprint 5 alone produced six agent-dispatch
failure modes [\ldots] Each recovery procedure is now codified in
\texttt{[[workflow\_parallel\_agent\_dispatch]]} memory with a specific
runbook. First salvage cost 30 min; sixth cost 5.''
(\texttt{docs/retros/sprint-5-retro.md:36})
\end{quote}

\textit{Mitigation (S5):} per-failure runbooks in project memory;
\texttt{isolation:"worktree"} default on every file-mutating dispatch
(\texttt{docs/retros/sprint-5-retro.md:75}).

\subsection{Firestore Security Rules --- actual, verbatim}

The rules use one helper, \texttt{isOwner(uid)} (line 5--7). The rubric
template referenced \texttt{isCreatingNow()}, \texttt{isImmutableField()},
\texttt{withinImmutability()} helpers --- these do \textbf{not} exist in
the shipped rules. The equivalent checks are inlined per-rule using
\texttt{request.time}, \texttt{diff().affectedKeys().hasOnly(...)}, and
\texttt{resource.data.createdAt} comparisons.

\paragraph{Moods: 24-hour edit/delete window + field allowlist}
(\texttt{firestore.rules:55--74}):

\begin{lstlisting}[language=Java]
allow update: if isOwner(uid)
  && request.time.year() == resource.data.createdAt.year()
  && request.time.month() == resource.data.createdAt.month()
  && request.time.day() == resource.data.createdAt.day()
  && request.resource.data.createdAt == resource.data.createdAt
  && request.resource.data.updatedAt is timestamp
  && request.resource.data.updatedAt == request.time
  && request.resource.data.diff(resource.data).affectedKeys()
     .hasOnly(['mood','intensity','text','mediaRefs','updatedAt'])
  && request.resource.data.intensity is int
  && request.resource.data.intensity >= 1
  && request.resource.data.intensity <= 5
  && request.resource.data.text is string
  && request.resource.data.text.size() <= 500
  && request.resource.data.mood in
       ['happy','calm','okay','sad','angry','anxious'];
\end{lstlisting}

\paragraph{Interventions: one-way opt-out toggle}
(\texttt{firestore.rules:282--286}):

\begin{lstlisting}[language=Java]
allow update: if isOwner(uid)
  && request.resource.data.diff(resource.data).affectedKeys()
     .hasOnly(['optedOut'])
  && resource.data.get('optedOut', false) == false
  && request.resource.data.optedOut == true;
\end{lstlisting}

\paragraph{Weekly gardens: write-once on archive}
(\texttt{firestore.rules:441--450}):

\begin{lstlisting}[language=Java]
allow create: if isOwner(uid)
  && weekId.matches('^\\d{4}-W\\d{2}$')
  && request.resource.data.weekId == weekId
  && request.resource.data.archivedAt is string;
allow update, delete: if false;
\end{lstlisting}

\texttt{diff().affectedKeys().hasOnly([...])} is used at lines 62, 133,
182, 230, 283 and 310 to enforce field allowlists on every collection
that permits update. Rules are exercised in CI via the Firestore
emulator: \texttt{.github/workflows/ci.yml:232--274} runs
\texttt{firebase emulators:exec --only firestore "pnpm test"} against
15 rule unit cases (WBS 2.3).

\subsection{Cloud Function \& secrets}

Seventeen Cloud Functions at \texttt{functions/src/*.ts}. Security
posture highlights:

\begin{itemize}[leftmargin=*]
  \item \textbf{Gemini API key} via
    \texttt{firebase-functions/params defineSecret('GEMINI\_API\_KEY')}
    at \texttt{geminiClient.ts:33}, \emph{not} in \texttt{.env}. The
    \texttt{.env} holds non-secret WebAuthn config only. The secret is
    lazily resolved via \texttt{.value()} at call time, never bundled
    in the client.
  \item \textbf{Rate-limit} (\texttt{rateLimit.ts:13--14}):
    \texttt{analyzeMoodText} $\le$ 10 calls / 60\,s;
    \texttt{analyzePatterns} $\le$ 1 call / 30\,s
    (\texttt{rateLimit.ts:34}). Backed by a Firestore transaction on
    \texttt{rateLimits/\{uid\}}.
  \item \textbf{PII discipline.} Not regex-based redaction --- the
    actual approach is length-only logging (``never log raw text, full
    prompt, or model rationale'', \texttt{analyzeMoodText.ts:256--257})
    plus a canary test at
    \texttt{functions/src/\_\_tests\_\_/analyzeMoodText.test.ts:453}
    that feeds the literal \texttt{"PII-CANARY-12345"} and asserts it
    never appears in any logger payload.
  \item \textbf{Secret-scan hook} (\texttt{.claude/hooks/settings.json:24--29})
    blocks commits matching
    \texttt{(AIza...|sk-...|xox...|ghp\_...|AKIA...)}.
\end{itemize}

The rubric prompt referenced \texttt{docs/security/} --- that directory
does \textbf{not} exist in this repo. Security-impacting decisions live
in ADRs 0008 (cooldown persistence), 0012 (Tier-3 determinism), 0013
(biometric gating), 0014 (WebAuthn fallback). Sprint-5 review findings
are summarised in \texttt{docs/retros/sprint-5-retro.md}.

\subsection{Crashlytics placement}

Crashlytics is initialised inside \texttt{runZonedGuarded} in
\texttt{apps/mobile/lib/main.dart} (lines $\sim$69--79):

\begin{lstlisting}[language=Java]
if (!kIsWeb) {
  FlutterError.onError =
      FirebaseCrashlytics.instance.recordFlutterFatalError;
  PlatformDispatcher.instance.onError = (error, stack) {
    FirebaseCrashlytics.instance.recordError(error, stack, fatal: true);
    return true;
  };
  await FirebaseCrashlytics.instance.setCrashlyticsCollectionEnabled(true);
}
\end{lstlisting}

The zone-guard at line $\sim$246 catches async errors not handled by
\texttt{FlutterError.onError}. Web is intentionally a no-op because the
Crashlytics web plugin is not registered.

\paragraph{Correction.} The rubric prompt implied that the structured
logger routes errors to Crashlytics. It does \textbf{not}. The logger
at \texttt{packages/core/lib/src/logger.dart} delegates only to
\texttt{dart:developer.log}, and a comment at line 5--6 explicitly puts
PII redaction on the call site. Errors reach Crashlytics through
\texttt{FlutterError.onError} and \texttt{runZonedGuarded}, not through
the logger. We could \emph{not} find a test asserting ``mood text never
reaches Crashlytics''; adding one is recommended.

\subsection{Structured logging}

\texttt{packages/core/lib/src/logger.dart} defines
\texttt{class Logger(String name)} with \texttt{debug}/\texttt{info}/
\texttt{warn}/\texttt{error} methods that emit via
\texttt{dart:developer.log()} with the instance name as the
filter tag. The ``tags-per-feature'' pattern in the rubric template is
\emph{convention}, not enforcement --- the Logger accepts any name; no
CI lint rejects an off-taxonomy tag.

at \texttt{tiered\_intervention\_dispatcher.dart:69--73} returns the
curated body before any AI repo call is reachable
(\texttt{tiered\_intervention\_dispatcher\_test.dart:106--161} asserts
\texttt{expect(ai.calls, isEmpty)}). The only rollback path for a Tier-3
issue is a client app update.
