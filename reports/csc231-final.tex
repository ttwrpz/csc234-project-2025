\section*{Executive Summary}
\addcontentsline{toc}{section}{Executive Summary}

\textbf{Problem.} Thailand has a documented shortage of clinical
mental-health practitioners; mobile interventions can extend reach with
small-to-moderate effect sizes ($g \approx 0.38$)
\autocite{firth2017meta}. A self-administered mood-tracker must
reconcile sustained-engagement gamification with strict clinical safety
guardrails.

\textbf{Solution.} MoodBloom is a cross-platform Flutter mood-tracker for
Android and Web. Users log moods with intensity 1--5, optionally accept
AI-suggested labels from Gemini via a Cloud Function proxy, visualise
their week as a living garden whose plants never die, and receive tiered
intervention notifications when the pure-Dart Pattern Engine detects
emerging distress patterns.

\textbf{Delivered.} Twelve pivot features across five sprints. 1018
automated tests pass at \texttt{v1.5}. Domain-layer line coverage 94.6\%
overall with every feature $\geq 80\%$ (Enterprise R1 gate). 14
architecture decision records, 9 handoff briefs, 4 sprint retrospectives,
1 Security Posture Report (GO with three conditions).

\textbf{Methodology.} Agile/Scrum with five sprints, multi-agent
orchestration via Claude Code with four named subagents (architect,
flutter-engineer, qa-engineer, security-reviewer), Plan Mode discipline
at every sprint kickoff, no-self-review rule.

\textbf{Outcome.} Release-candidate \texttt{v1.5} tagged locally on
\texttt{feat/s5-v1.5-final}. Final Security Posture Report: GO with
three conditions (D-M01 transitive HIGH \texttt{pnpm} advisories filed
as v1.6 chore; skin-system branch merged in \texttt{ed2cd755};
cross-platform runbook done-criteria checklist to be confirmed on
Android emulator + Chrome web before pushing the tag).

\section{Introduction}

Thai young adults experience emerging mental-health needs at a rate that
outpaces clinical capacity. Smartphone-based interventions show
small-to-moderate efficacy per Firth et al.\ 2017's meta-analysis of
randomised controlled trials \autocite{firth2017meta}. Mood tracking is a
well-evidenced subset \autocite{kauer2012jmir,bakker2018moodprism}.

\textbf{Scope.} Cross-platform Flutter for Android (min-SDK 21) and Web
(PWA). Firebase backend (Auth, Firestore, Storage, Functions, FCM,
Remote Config, Crashlytics). Single language model: Gemini 2.5-flash via
a Cloud Function proxy --- never called directly from the client.

\textbf{Objectives.} (1) Ship a release-candidate by May 19, 2026; (2)
domain-layer line coverage $\geq 80\%$; (3) WCAG 2.2 AA contrast on both
themes; (4) cold-start $<2\,$s on mid-range Android; (5) zero
HIGH/CRITICAL security advisories at release.

\section{Software Architecture}

Three-layer rule per feature folder: \texttt{presentation/},
\texttt{domain/}, \texttt{data/}. Domain folder has \textbf{zero
imports} of \texttt{package:flutter/*},
\texttt{package:firebase\_*/*}, or
\texttt{package:cloud\_firestore/*}. Enforced three ways: CI grep,
preWrite hook, code review.

\textbf{Nine pure-Dart Domain Engines} power MoodBloom's therapeutic
logic: \texttt{MoodScore}, \texttt{GardenHealthEWMA},
\texttt{Atmosphere}, \texttt{PatternEngine},
\texttt{TieredInterventionDispatcher}, \texttt{CooldownGuard},
\texttt{QuoteLibrary + QuoteSafetyFilter}, \texttt{DisclaimerService},
\texttt{HarvestScheduler}.

\textbf{The Tier 3 Determinism Fence (ADR-0012).} Tier 3 must NEVER
invoke Gemini. Defended at five Dart layers + one server layer:

\begin{enumerate}[leftmargin=*]
\item \textbf{Type system} --- \texttt{enum AiAllowedTier \{ one, two \}}; \texttt{Tier.three} cannot satisfy the parameter type.
\item \textbf{Dispatcher hard branch} --- \texttt{Tier.three} arm calls \texttt{QuoteLibrary.pickTier3} directly and returns.
\item \textbf{Unit test} --- \texttt{recordingFake.calls.isEmpty} unconditionally.
\item \textbf{Controller test} --- re-asserts at controller layer.
\item \textbf{Integration test} --- full app with production controller/dispatcher/library/filter; only AI repo mocked; asserts empty calls.
\item \textbf{Server schema} --- \texttt{suggestQuote.ts} rejects \texttt{tier: 3} with \texttt{HttpsError('invalid-argument')}.
\end{enumerate}

\section{Conclusion \& Lessons Learned}

\textbf{What worked.} Plan Mode front-loads design (ADR-0010, ADR-0011,
ADR-0012, HB-007 were the load-bearing examples); domain-purity
enforcement at three layers (preWrite hook + CI grep + code review)
caught zero violations across the codebase; no-self-review caught two
CRITICAL bugs before merge in S3; multi-layer fences for safety-critical
invariants (Tier 3) are worth the 1--2 hours of architect time.

\textbf{What didn't.} Parallel agents share state in ways that aren't
obvious (six salvages in S5); golden tests are too brittle for a small
team on Windows-vs-CI (deleted in v1.5 trim); user testing surfaced
more than security audits did.

\textbf{For future student teams using AI-assisted enterprise
workflows:} write the ADR before the code; default file-mutating
dispatches to \texttt{isolation:"worktree"}; verify the agent committed
before believing its ``done'' report; budget 30\% of the sprint clock
for orchestrator-side salvage; treat the user-testing pass as a P0
deliverable; codify recovery procedures the first time they happen, not
the third.
